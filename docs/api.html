The contract

The request, the reply, the two traits, and the event stream reader.

moonmuse

moonbitstack/moonmuse

The shared vocabulary: messages, requests, replies, the two contracts, and the server-sent-events reader every streaming client needs.

traitCounter
pub(open) trait Counter { fn count(Self, Request) -> Int32 raise LlmError }

How many tokens a request costs, before anyone answers it. A tokenizer is a large table that most callers do not need, so the contract lives here and the implementation that loads a vocabulary lives in moonmuse/count: a gateway is handed a counter, and a deployment that has no vocabulary says so instead of inventing a number.

traitDialect
pub(open) trait Dialect { fn name(Self) -> String fn request(Self, Request) -> Call raise LlmError fn reply(Self, Int32, @json.Json) -> Reply raise LlmError fn delta(Self, Frame, Turn) -> Array[Delta] raise LlmError fn routes(Self) -> Array[Route] fn parse(Self, Route, @json.Json) -> Asked raise LlmError fn answer(Self, Reply) -> @json.Json fn answer_embed(Self, String, Array[Array[Double]]) -> @json.Json fn answer_count(Self, Int32) -> @json.Json fn answer_models(Self, Array[ModelInfo]) -> @json.Json fn answer_at(Self, RouteKind, Reply) -> @json.Json fn frame(Self, Delta, Turn) -> Array[Frame] fn error(Self, LlmError) -> (Int32, @json.Json) }

One vendor's wire format, read and written in the same place. The client half turns a Request into a Call and a body into a Reply; the server half turns a body into a Request and a Reply into a body. Because both halves live here, a gateway that speaks a format out cannot drift from the client that speaks it in.
